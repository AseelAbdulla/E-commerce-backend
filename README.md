E-commerce Backend

نظام التجارة الإلكترونية وإدارة المنتجات والطلبات والمستخدمين

مشروع Backend مبني باستخدام Laravel 12، يوفر واجهات برمجية RESTful API لإدارة عمليات التجارة الإلكترونية، بدءًا من تسجيل المستخدمين وتصفح المنتجات، مرورًا بسلة المشتريات وإنشاء الطلبات، وصولًا إلى إدارة المخزون والصلاحيات وطلبات الاستيراد.

يهدف المشروع إلى توفير بنية خلفية منظمة وقابلة للتوسع، مع دعم المصادقة باستخدام Laravel Sanctum، وإدارة الأدوار والصلاحيات، والتعامل مع البيانات متعددة اللغات.

✨ المميزات الرئيسية

1. المصادقة وإدارة المستخدمين

يوفر النظام واجهات للمستخدمين تشمل:

- إنشاء حساب جديد.
- تسجيل الدخول.
- تسجيل الخروج.
- عرض بيانات المستخدم الحالي.
- تحديث بيانات الملف الشخصي.
- تغيير كلمة المرور.
- طلب رابط إعادة تعيين كلمة المرور.
- إرسال إشعار التحقق من البريد الإلكتروني.
- التحقق من حالة الحساب.

يستخدم المشروع Laravel Sanctum لإنشاء وإدارة رموز الوصول (Bearer Tokens).

2. إدارة الأدوار والصلاحيات

يعتمد المشروع على حزمة Spatie Laravel Permission لتطبيق مفهوم التحكم بالوصول المعتمد على الأدوار والصلاحيات (Role-Based Access Control).

من الأدوار المستخدمة في النظام:

- "admin"
- "employee"
- "local-client"
- "import-client"

وتشمل إدارة الصلاحيات عمليات مثل:

- عرض المستخدمين.
- إنشاء المستخدمين.
- تعديل المستخدمين.
- حذف المستخدمين.
- إدارة الأدوار.
- إدارة الصلاحيات.
- إسناد الصلاحيات للأدوار.

3. إدارة المنتجات

يوفر النظام واجهات لإدارة المنتجات، وتتضمن بيانات المنتج:

- اسم المنتج.
- الوصف.
- التصنيف.
- رمز المنتج SKU.
- السعر الأساسي.
- حالة الخصم.
- سعر الخصم.
- الكمية المتوفرة.
- الحد الأدنى للمخزون.
- حالة المنتج.

كما يدعم:

- عرض المنتجات.
- عرض تفاصيل المنتج.
- عرض المنتجات الأكثر مبيعًا.
- إدارة صور المنتجات.
- إدارة وحدات المنتجات.
- متابعة تقييمات المنتجات.

4. إدارة التصنيفات

يسمح النظام بتنظيم المنتجات ضمن تصنيفات، مع توفير واجهات عامة لعرض التصنيفات وتفاصيلها، وواجهات إدارية لإضافة التصنيفات وتعديلها وحذفها.

5. وحدات المنتجات والأسعار

يدعم المشروع ربط المنتج بوحدات قياس متعددة من خلال نموذج "ProductUnit".

يساعد ذلك في تمثيل المنتجات التي يمكن بيعها بأكثر من وحدة، مع إمكانية تنظيم أسعارها وبياناتها وفق تصميم النظام.

6. سلة المشتريات

يوفر النظام عمليات إدارة سلة المشتريات للمستخدم المسجل:

- عرض محتويات السلة.

- إضافة عناصر إلى السلة.

- تفريغ السلة بالكامل.

7. إدارة العناوين

يدعم النظام ربط المستخدم بعناوينه، وتتضمن بيانات العنوان:

🔐 المصادقة وحماية API

يعتمد المشروع على Laravel Sanctum لتوفير المصادقة باستخدام الرموز الشخصية.

تعمل آلية المصادقة بصورة عامة كالتالي:

1. يرسل المستخدم بيانات تسجيل الدخول.
2. يتحقق النظام من صحة بيانات المستخدم.
3. ينشئ النظام رمز وصول (Access Token).
4. يرسل المستخدم الرمز مع الطلبات المحمية.
5. يتحقق Laravel Sanctum من الرمز قبل السماح بالوصول إلى المسارات المحمية.

يتم إرسال الرمز في ترويسة الطلب:

Authorization: Bearer YOUR_ACCESS_TOKEN
Accept: application/json

وتستخدم المسارات المحمية Middleware:

auth:sanctum

كما يستخدم المشروع Middleware للأدوار والصلاحيات لتقييد الوصول إلى وظائف الإدارة.

🚀 تثبيت المشروع وتشغيله

1. استنساخ المستودع

git clone https://github.com/AseelAbdulla/E-commerce-backend.git

ثم الانتقال إلى مجلد المشروع:

cd E-commerce-backend

2. تثبيت حزم PHP

composer install

3. إعداد ملف البيئة

في Windows:

copy .env.example .env

في Linux أو macOS:

cp .env.example .env

4. إنشاء مفتاح التطبيق

php artisan key:generate

5. إعداد قاعدة البيانات

يمكن استخدام SQLite وفق الإعداد الافتراضي في ".env.example"، أو إعداد اتصال MySQL.

مثال إعداد MySQL:

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=ecommerce
DB_USERNAME=root
DB_PASSWORD=

تأكد من إنشاء قاعدة البيانات قبل تشغيل الترحيلات.

6. تشغيل Migrations وSeeders

php artisan migrate --seed

يستدعي "DatabaseSeeder" مجموعة من Seeders الخاصة بالمستخدمين والأدوار والإعدادات والتصنيفات والمنتجات والطلبات وغيرها.

تنبيه: لا تستخدم "migrate:fresh" على قاعدة بيانات تحتوي على بيانات مهمة؛ لأنه يحذف الجداول ويعيد إنشاءها.

7. إنشاء رابط التخزين

php artisan storage:link

8. تشغيل الخادم

php artisan serve

سيكون التطبيق متاحًا افتراضيًا على:

http://127.0.0.1:8000

وتكون واجهات API تحت:

http://127.0.0.1:8000/api

يتطلب هذا الأمر توفر Node.js وnpm وحزم المشروع اللازمة.

تشغيل الاختبارات

يمسح إعدادات التخزين المؤقت ثم يشغل اختبارات Laravel.

مسؤوليات المجلدات

- "app/Models": نماذج قاعدة البيانات والعلاقات.
- "app/Http/Controllers": استقبال طلبات HTTP وتنفيذ العمليات.
- "app/Services": تنظيم منطق الأعمال.
- "app/Enums": القيم الثابتة المستخدمة في النظام.
- "database/migrations": إنشاء وتعديل الجداول.
- "database/seeders": إدخال البيانات الأولية والتجريبية.
- "routes/api.php": تعريف واجهات API.
- "tests": اختبارات التطبيق.

🔒 ممارسات الأمان

يراعي المشروع عددًا من آليات الحماية، من أبرزها:

- المصادقة باستخدام Laravel Sanctum.
- حماية المسارات باستخدام Middleware.
- إدارة الأدوار والصلاحيات.
- التحقق من بيانات الطلبات.
- تخزين كلمات المرور باستخدام آليات Hashing في Laravel.
- استخدام رموز وصول للمستخدمين.
- تقييد الوصول إلى عمليات الإدارة وفق الأدوار والصلاحيات.

ينبغي عدم نشر ملف ".env" أو تضمين كلمات المرور والمفاتيح السرية في مستودع GitHub.

🚧 أفكار للتطوير المستقبلي

يمكن تطوير النظام مستقبلًا بإضافة أو تحسين:

- توثيق API باستخدام OpenAPI / Swagger.
- بوابات دفع إلكترونية.
- تكامل مع خدمات الشحن والتوصيل.
- تقارير أكثر تفصيلًا للمبيعات والمخزون.
- تحسين تغطية الاختبارات الآلية.
- تحسين نظام الإشعارات.
- سجل لحركة المخزون.
- تحسين البحث والتصفية.
- تحسين الأداء باستخدام Cache وQueue عند الحاجة.

هذه مقترحات تطويرية وليست تأكيدًا على وجودها في النسخة الحالية.
